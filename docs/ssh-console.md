# Interactive SSH console

Open **SSH connection** in a proxy card's actions menu. The console uses the existing management credentials from Settings and the shared Rust SSH authentication / known-host verification. A new session opens one SSH connection and one PTY shell. Commands keep their privilege and configuration context. Navigation does not disconnect the session; Disconnect or closing the app ends it. New session reconnects explicitly without replaying commands.

Live connects directly to the appliance on port 22. Mocked Data always connects directly to `127.0.0.1:2222` and starts the same dummy CLI as Backup Manager. Switching profiles closes SSH consoles belonging to the other profile. SSH does not use the HTTP proxy.

The left panel indexes commands with their timestamps. Click an entry to jump to its output. Outputs can be collapsed and copied; both the history and transcript use TanStack Virtual. Command output streams to the existing app cache, with only 32 KiB segments loaded into the renderer. Previous / Next reads the complete output incrementally, and Follow displays the latest segment. Copy reads the full current output explicitly. A running command can still produce more output after a copy.

The command composer supports multiline paste, preserving indentation and empty lines. Enter sends the current text; Shift+Enter inserts a newline. For inline policy editing, send `inline policy local EOF`, paste and send the policy body, then send `EOF` separately when ready. The console never generates or appends the delimiter. Windows CRLF and LF are normalized to one PTY Enter per line, without flattening or adding an extra Enter to an already terminated block. Input is limited to 1 MiB per submission; sensitive responses remain single-line with an 8 KiB limit. Sending and receiving run concurrently so larger blocks do not block output processing.

The input is line-oriented. Appliance prompts determine when a command completes. Password / passphrase / verification challenges switch to a hidden input and responses stay with the current command, outside command history. Sensitive response can be selected manually for other confidential challenges. Recognized secret values are redacted even if echoed in fragmented SSH packets. Commands themselves and appliance configuration output can contain sensitive data; they are ordinary session cache files, not a credential vault.

Use Continue / Space for the appliance pager and Ctrl+C to interrupt. Other interactive replies can be sent through the input while a command is running. This is an appliance CLI transcript, not an ANSI terminal emulator for full-screen editors. A quiet interval alone never completes a command without a recognized prompt. Sessions use SSH keepalives; a lost connection is surfaced and requires a new session.

Session metadata and command history persist in version-1 JSON checkpoints beside the existing `ssh-<timestamp>-<sequence>/<block>.txt` output files in the application cache. Commands are checkpointed before transmission, with output/metadata synchronized approximately once per second and at disconnection. Two alternating snapshots are written through synchronized temporary files; restoration chooses the newest valid snapshot (including a complete temporary snapshot after an interrupted rename). A damaged session does not prevent other sessions from loading. Truncated output is reconciled with the bytes actually present; output blocks newer than a recoverable snapshot are labelled as recovered output when their command metadata is unavailable. An abrupt termination can leave the last completion flag stale; it never causes commands to replay.

History loads on the first session list or explicit connection request after startup. Restored sessions are always **Disconnected**, with no live input channel, socket, automatic reconnection, credential retrieval or command replay. Address, proxy/ISG target kind and Live/Mocked Data remain in the snapshot and retain the existing workspace filtering. Passwords, sensitive responses, input queues, remote prompt text and runtime errors are not included in metadata. The existing output redactor still removes recognized secret values; Unix session directories/files are created with owner-only permissions. Ordinary commands and configuration output can still contain secrets when not marked as sensitive.

Retention is explicit: no automatic expiry or eviction. Remove session deletes its snapshots and output together. The existing limits now apply across restarts: 32 retained sessions in total (all profiles/targets) and 5,000 command blocks per session. Reaching a limit is reported without silently discarding history. Files remain in Tauri's existing cache location; clearing that cache removes history. Sessions created by older versions have output files but no recoverable appliance/profile/command metadata, so they are preserved on disk without guessing their ownership or listing them. If every checkpoint of a session is corrupt or uses an unknown schema, its files are also preserved without exposing them under another appliance.
